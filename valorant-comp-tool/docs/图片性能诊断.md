# 图片加载卡顿诊断与优化报告

> 诊断时间：2026-08-30 · 针对当前版本（不做大版本重构，均为可直接落地的优化）

## 一、结论先行

**卡顿确实主要由“在线读取大图”导致，且是“图太大 + 一次性全量加载”双重问题。** 经实测（`curl -I` 取 `Content-Length`）：

| 资源 | 单张体积 | 页面一次加载数量 | 合计 |
| --- | --- | --- | --- |
| 地图全景图 `splash.png` | **1.5 ~ 5.4 MB**（莲华 5.4MB、天枢 5.2MB） | 地图页 7 张 | **约 22 MB** |
| 英雄立绘 `fullportrait.png` | **约 628 KB** | 英雄图鉴 29 张 + 每次开英雄池编辑器再 29 张 | **约 18 MB / 次** |
| 英雄头像 `displayicon.png` | 约 410 KB | 名单缩略、点位列表若干 | 视数量 |

- 地图**卡片缩略图**原来直接用 2–5MB 的 `splash` 原图，仅仅为了显示一个 16:9 小图 → 极度浪费。
- 英雄图鉴一次性渲染 29 张 628KB 立绘；打开英雄池编辑器又**重复渲染 29 张**（DOM 里其实存在两套 `.agent-card`）→ 首屏和切页都拖。
- 所有图来自远程 CDN `media.valorant-api.com`，**离线 / 弱网必然卡或裂图**。

## 二、可能原因逐条排查

1. **✅ 主因：图片源文件过大**（地图 splash 平均 3MB+）。卡片缩略只需几十 KB，却下了原图。
2. **✅ 主因：一次性全量加载 + 重复加载**（图鉴 29 张 + 编辑器 29 张同时在 DOM）。
3. **✅ 次因：未预连接 CDN**。首次请求要经历 DNS→TCP→TLS 握手，`media.valorant-api.com` 与 `cdn.jsdelivr.net` 都没 `preconnect`。
4. **✅ 次因：解码阻塞**。大图同步解码会阻塞主线程，滚动/切页时掉帧。
5. **⚠️ 相关：完全依赖公网 CDN**。国内访问 Cloudflare 有时慢；离线不可用。
6. **⚠️ 相关：无加载占位/失败兜底**。图未回来时是空白，观感像“卡死”。

## 三、优化方案（本次已实施 ✅ / 可选进阶 ⬜）

### ✅ 1. 地图缩略图改用 `listViewIcon`（最大收益）
卡片、下拉、点位面板的“非主视觉”地图图，从 `splash`（2–5MB）换成 `listViewIcon`（约 60KB）。**地图页从 ~22MB 降到 ~0.4MB，降幅 98%+。** 只有点进详情页的“大 Banner”才用 `splash` 原图。

### ✅ 2. 英雄卡片缩略改用 `displayIcon`（半身/立绘只在必要处用）
图鉴/英雄池网格的卡片用 `displayIcon`（约 410KB，且尺寸更适合方形卡）而非 `fullportrait`；生成结果与详情弹窗才用 `fullportrait`。同时**英雄池编辑器改为懒渲染**（展开某位置才建卡片），避免一次性 29+29 张。

### ✅ 3. `<img>` 全量加 `loading="lazy"` + `decoding="async"`
视口外不下载、解码不阻塞主线程。并给图片容器加**骨架背景 + `onerror` 兜底占位**，弱网时先有框架不至于“看着像卡死”。

### ✅ 4. `preconnect` / `dns-prefetch` 预连接 CDN
在 `<head>` 预连 `media.valorant-api.com` 与 `cdn.jsdelivr.net`，省去首图的握手时间。

### ✅ 5. 图片并发/缓存友好
统一通过 `VCT.assets` 生成 URL（浏览器/CDN 层面天然按 URL 缓存），切页不重复下大图。

### ⬜ 6.（进阶，需版本更新/额外资源，未做）本地化素材
把常用图下载到 `assets/` 做“完全离线版”，或接一层图片压缩代理（如 `images.weserv.nl`）在线压缩 + WebP。**本次按“不做大版本更新”的要求未纳入**，已在 README/报告中标注为后续可选项。

## 四、优化前后预估

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 地图页首屏 | ~22 MB | **~0.4 MB**（7 张缩略图） |
| 英雄图鉴首屏 | ~18 MB 一次性 | 视口内按需，`displayIcon` + lazy |
| 打开英雄池编辑器 | 再 +18 MB（重复 29 张） | 懒渲染，仅展开位置才加载 |
| 首图握手 | 每次冷连接 | preconnect 复用连接 |

> 说明：以上均为前端加载策略优化，**不改变任何数据与业务逻辑**，属安全的性能改造。
